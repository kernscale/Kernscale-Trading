# Security policy

## Supported version

Security fixes target the current `main` branch. Older snapshots and forks do not
have a separate security support commitment.

## Report a vulnerability privately

Use GitHub's [Report a vulnerability](https://github.com/kernscale/Kernscale-Trading/security/advisories/new)
form. Do not disclose vulnerabilities, credentials or private research in public
issues, pull requests, Actions logs or screenshots.

Include the affected commit, component, impact and minimal steps to reproduce
using synthetic data. If a reproduction contains sensitive information, describe
it first and agree a safe exchange with a maintainer.

Maintainers will assess the report and coordinate a fix and disclosure. Do not
probe deployed services, access another member's data or test with real trades
without separate permission from the service owner.

## Exposed credentials

Revoke or rotate a confirmed exposed credential with its issuer promptly, and
notify the maintainers privately. Deleting a file or rewriting Git history does
not invalidate the credential or remove copies already downloaded.

Public source access does not grant access to Kernscale's deployed application,
private research, provider accounts or infrastructure.
